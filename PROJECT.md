# Xact Web Sandbox — Project Constitution

## Product position

**Xact — The Commit Layer for Agentic Web**

**Reason when necessary. Execute Xactly.**

## North star

> Resolve everything deterministically possible. Execute only what is independently authorized. Reason only about what remains unresolved.

## Invariant

> **Reasoning may propose a consequence. Only Xact may commit one.**

## Product objective

Build a polished, modular web sandbox that demonstrates safe autonomous web interaction through replaceable execution substrates including WebMCP, DOM/browser interaction, Vision, native/API operations, and future protocols.

The sandbox must make clear that execution capability is not execution authority.

## Development priority

1. Correctness
2. Safety boundary
3. Demonstrability
4. Modularity
5. User experience
6. Performance
7. Additional features

If implementation convenience conflicts with the architecture, the architecture wins.

## Multi-agent rule

No development agent may silently redefine Xact terminology or redesign core architecture. Architectural changes must be proposed before implementation.
